EasySD - technical documentation
===============================

1. FAT32 - detection of the first MBD/MBH image
------------------------------------------------

EasySD does not determine the first disk image from the order of directory
entries in the FAT32 root directory.

The complete FAT32 root directory cluster chain is searched. For every
MBD/MBH file its starting cluster is obtained. The file with the lowest
starting cluster is considered the physically first image and its absolute
LBA is calculated.

This is necessary because the order of FAT32 directory entries does not
necessarily correspond to the physical order of files in the data area.

Therefore image filenames do not determine disk order. The user may use
descriptive filenames such as:

    ASSEMBLY.MBD
    MY_CODE.MBD
    GAMES_A.MBD
    GAMES_B.MBD

The important condition is that MBD/MBH images are physically stored
contiguously. EasySD calculates subsequent BSDOS disks by a fixed offset
from the physically first image.

TEST CASE - 2026-08-25
----------------------

Test FAT32 partition:
    cluster size:        4096 bytes (8 sectors)
    root cluster chain:  2 -> 7 -> 8
    first physical MBD:  001_NMI165.MBD
    start cluster:       9
    absolute LBA:        29896760

The old EasySD algorithm searched only the first 8 directory entries and
incorrectly selected 076.MBD as the first image.

The new algorithm searched the FAT32 root cluster chain and selected
001_NMI165.MBD because it had the lowest starting cluster.

All 255 BSDOS disks were subsequently tested successfully.

IMPLEMENTATION NOTE
-------------------

When incrementing a 32-bit LBA implemented as two 16-bit words on Z80,
INC HL must not be followed by a conditional jump expecting flags to
indicate 16-bit overflow. INC HL does not modify the Z80 flags.

This caused an important bug during development: the first sector of a
root cluster was read correctly, but subsequent sectors could be read
from an incorrect 32-bit LBA.
